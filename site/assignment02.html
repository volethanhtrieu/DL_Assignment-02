Assignment 02 — Emotion Text Classification

We classify short English texts from dair-ai/emotion into six emotions and compare a TF-IDF + Logistic Regression baseline with two fine-tuned transformers, DistilBERT and BERT, and with a frozen-encoder DistilBERT (main controlled experiment). Every choice was made on validation; the test set was used once. On test, the selected model (DistilBERT full fine-tune, seed 42) reaches Macro-F1 0.8902 and accuracy 0.9270 (three seeds: 0.8861 ± 0.0038) against 0.8548 for the best baseline. BERT ties with DistilBERT (0.8878 ± 0.0004) at about twice the cost, and a frozen encoder fails (0.4210 ± 0.0020).

01

Problem statement

Single-label multiclass classification: given one short English text, predict one of six emotions (sadness, joy, love, anger, fear, surprise). The prediction unit is one text. Recognising emotion in short, informal writing is a common building block for feedback analysis, support triage and social-media monitoring. The main difficulties are strong class imbalance (joy 33.5% vs surprise 3.5% of train), very short texts (median 17 words), emotions that overlap in wording (joy and love), and machine-generated labels with some conflicting duplicates.

04

Methodology: baseline and pretrained models

A lexical baseline shows how far word and bigram counts go on this data; the EDA (section 02) suggested labels follow emotion keywords, so a strong baseline was expected. DistilBERT is the pretrained model from the approved plan: it reads the whole text in context (word order, negation). BERT is the larger encoder it was distilled from. All models use the same filtered splits. The transformers read the minimal text (text_min: NFC, lowercase, whitespace); the selected baseline reads the aggressive text (stopwords removed, negations kept), chosen on validation in experiment 3 (section 07).

Comparison and discussion

Transformer vs baseline. On test, DistilBERT (seed 42) reaches Macro-F1 0.8902 and accuracy 0.9270 against 0.8548 and 0.8905 for the selected baseline (+0.0354 / +0.0365). It is better on all six classes, most on love (+0.060) and least on anger (+0.022). Text by text, 124 test texts are right only for DistilBERT and 51 only for the baseline (McNemar exact p ≈ 3 × 10−8). The gain is largest where one emotion word is not enough: long texts (≥ 35 words, accuracy 0.920 vs 0.806), texts with "but" (0.929 vs 0.854) and negated texts (0.912 vs 0.857); on short texts the two are close (0.943 vs 0.924). The price is about 45× the CPU latency per text (59.6 vs 1.32 ms), 650× the parameters and 219× the file size.

BERT vs DistilBERT. BERT reaches 0.8878 ± 0.0004 on test against 0.8861 ± 0.0038 (validation 0.9163 ± 0.0032 vs 0.9155 ± 0.0020). The per-seed differences change sign on both splits, and on test 62 texts are right only for BERT and 60 only for DistilBERT (McNemar p ≈ 0.93): the two models are tied. BERT costs 1.64× the parameters, 1.89× the training time and 2.00× the CPU latency, so DistilBERT is kept.

Validation → test. The strong models lose 0.01–0.03 Macro-F1 from validation to test, mostly on surprise (DistilBERT −0.082; only 66 test texts, so one error moves its F1 by about 0.015) and love (−0.033); sadness and fear barely change. Part of the drop is expected, because the checkpoint epoch and the model were chosen on validation. The ranking of all setups is the same on both splits.

Result: frozen 0.4191 ± 0.0061 vs full 0.9155 ± 0.0020 on validation (test 0.4210 ± 0.0020 vs 0.8861 ± 0.0038). (1) holds: full is higher on every seed and the gap (0.4965) is far above 2 × 0.0061. 09

Limitations and conclusion

Limitations. Data: one English dataset of short informal texts with machine-generated labels; 51 of 52 repeated-text groups had conflicting labels and 14 test texts keep disputed labels; texts have no apostrophes ("I'll" appears as ill); near-duplicates and author overlap could not be checked; surprise has only 66 test texts. Method: no hyperparameter search for any model; the frozen-encoder result holds for one recipe; single-label output although some texts express several emotions. Experiments: three seeds per transformer and one run per baseline setting; timings come from a shared Colab machine (one CPU thread, one T4) and GPU memory was not measured.

Conclusion. Does fine-tuning a pretrained transformer beat a TF-IDF baseline on six-class emotion classification, and at what cost? Yes: DistilBERT full fine-tune reaches test Macro-F1 0.8902 (accuracy 0.9270) against 0.8548 for the best baseline, better on every class and most on texts that need context, at about 45× the CPU latency. BERT gives no measurable gain for twice the cost, and freezing the encoder does not work under the same recipe. Two cheap choices, class weights and stopword removal with a negation keep-list, lift the baseline from 0.7289 to 0.8548. The remaining errors lie between close emotions and partly reflect doubtful labels.

Future work. Per-class thresholds tuned on validation for love and surprise; re-checking the conflicting and all-models-wrong labels, or multi-label targets; a tuned learning rate and more epochs for the frozen head; a smaller or quantised DistilBERT for CPU use.

import unicodedata
import joblib
from transformers import AutoTokenizer, AutoModelForSequenceClassification

# Selected model: the folder distil_full_min/ (from checkpoints_final.zip or A2/checkpoints/)
tokenizer = AutoTokenizer.from_pretrained("distil_full_min")
model = AutoModelForSequenceClassification.from_pretrained("distil_full_min").eval()

def text_min(text):
    # Same preprocessing as in training: NFC, lowercase, single spaces
    return " ".join(unicodedata.normalize("NFC", text).lower().split())

enc = tokenizer(text_min("i feel so lucky today"), truncation=True, max_length=128, return_tensors="pt")
pred = model(**enc).logits.argmax(dim=1).item()
print(model.config.id2label[pred])

Rebuild every checkpoint

  1. Open the notebook in Colab (link above) and choose Runtime → Change runtime type → T4 GPU.
  2. Optional: add WANDB_API_KEY to Colab Secrets. Without it the notebook continues with USE_WANDB = False.
  3. In the config cell set LOAD_CKPT = False to retrain everything. With LOAD_CKPT = True, any run that already has a checkpoint in MyDrive/DL/A2/checkpoints/ is loaded and the others are trained.
  4. Runtime → Run all. Training takes about 45 minutes in total (sum of the train times above). A run counts as finished only when its train_info.json exists, so a run cut off by a disconnect is trained again.
  5. The last cell writes results/checkpoints.csv (run, Drive path, size, best epoch, wandb run id) and zips the results.
